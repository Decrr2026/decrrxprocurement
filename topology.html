What changes, what doesn't

Two boxes get new jobs. Everything else is untouched.

Repo changed role

GitHub

Goes private. Stops serving the site — it's purely where the code lives and where you make edits, same as always.

Static host new

Cloudflare Pages

Takes over from GitHub Pages. Watches the private repo and redeploys automatically every time you save a change.

Database + API

Supabase

No change. Still the only place your vendor, bill, payment and material data actually lives.

Proxy

Cloudflare Worker

No change. Still the only place your Claude API key is stored — now simply a neighbor of Cloudflare Pages in the same account.

Model

Claude API

No change. Still only ever reached through the Worker, never directly from the browser.

You

Editing workflow

Stays familiar — you still edit in GitHub's editor and commit. The only difference is the site updates itself after, instead of being what you edited directly.

What this actually fixes

Why bother

Today, anyone can open your GitHub repo and read the app's source code, because GitHub Pages' free tier only serves from public repositories. Once the repo is private and Cloudflare Pages does the serving instead, the published app looks identical to visitors, but the underlying code is no longer browsable by anyone outside your organization.

What stays true either way

Your actual business data was never at risk from this — Supabase enforces authenticated-only access on every table regardless of who can see the app's code. This change is about hiding your source code and business logic, not about protecting data that was already protected.
